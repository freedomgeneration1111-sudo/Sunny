# Focus Lab Productions Codebase — A Beginner’s Guided Tour

Think of this repository as a small theater production. The routes are the stages, components are reusable scenery, `lib/` contains scripts and production facts, `public/` is the prop room, and Next.js assembles everything into static HTML for Cloudflare.

## 1. The technology stack

### Next.js 15

Next.js is the framework coordinating the website. It converts folders into URLs, renders React components, handles metadata, fonts, and images, and creates the final static website.

This project uses the App Router. A file such as:

```text
app/weddings/page.tsx
```

becomes:

```text
/weddings/
```

### React 19

React lets the site be assembled from reusable components:

```tsx
<Button href="/pricing">Explore Pricing</Button>
```

Most components render HTML on the server. Components that need browser state—such as the header, FAQ accordion, pricing planner, and inquiry form—begin with:

```tsx
"use client";
```

### TypeScript

TypeScript adds rules about what data may look like. For example, `MediaAsset` requires every registered image to have an ID, source, alt text, truth status, aspect ratios, and purpose.

If a required field is missing, TypeScript reports it before deployment.

### Tailwind CSS 4

Tailwind supplies small CSS utility classes inside components:

```tsx
<div className="rounded-card border border-border bg-surface p-6">
```

Named colors, radii, spacing, and typography are defined centrally in `app/globals.css`.

### PostCSS

PostCSS transforms CSS during the build. Its main job here is running Tailwind CSS.

### Playwright

Playwright opens the site in Chromium and tests it like a visitor:

- Visits important routes
- Clicks menus
- Scrolls the homepage
- Advances through the inquiry form
- Tests desktop and mobile layouts
- Detects horizontal overflow

### ESLint

ESLint reviews the source for suspicious React, Next.js, TypeScript, and accessibility patterns.

### Wrangler and Cloudflare Workers Static Assets

Next.js exports the finished site into `out/`. Wrangler serves or deploys that folder through Cloudflare Workers Static Assets.

```text
React components
       ↓
Next.js build
       ↓
Static HTML, CSS, JavaScript, and images in out/
       ↓
Cloudflare Workers Static Assets
       ↓
Visitor's browser
```

## 3. Build and tool configuration

### `next.config.ts`

Controls Next.js.

```ts
output: "export"
```

makes a static site.

```ts
trailingSlash: true
```

exports routes as folders such as `out/about/index.html`.

```ts
images: { unoptimized: true }
```

is required because this static deployment has no Next.js image-processing server.

### `tsconfig.json`

Configures TypeScript.

Important settings include:

- `strict: true`
- `noUncheckedIndexedAccess: true`
- `noEmit: true`
- `@/*` import aliases

The alias lets the project write:

```ts
import { config } from "@/lib/config";
```

instead of fragile paths such as `../../../lib/config`.

### `next-env.d.ts`

Generated by Next.js to provide framework types. Developers normally do not edit it.

### `eslint.config.mjs`

Enables Next.js, Core Web Vitals, and TypeScript lint rules. It narrowly ignores generated output and `next-env.d.ts`.

### `postcss.config.mjs`

Connects Tailwind CSS 4 to PostCSS.

### `playwright.config.ts`

Configures browser tests. It starts the development server, tests desktop Chromium and a Pixel 5 profile, and stores traces on retries.

### `wrangler.jsonc`

The Cloudflare deployment configuration:

```json
"assets": {
  "directory": "./out"
}
```

Cloudflare serves the static files generated by Next.js.

The site-wide design foundation. It defines:

- Focus Lab orange
- Canvas and surface colors
- Text and border colors
- Card and control radii
- Header height
- Section spacing
- Typography
- Focus-visible behavior


becomes a Tailwind class such as:

```tsx

```

## 5. The homepage

### `app/page.tsx`

The root `page.tsx` becomes `/`.

It assembles the homepage:

1. Cinematic hero
2. Credibility strip
3. Event-family cards
4. One Crew section
5. Capability families
6. Pricing preview
7. How It Works
8. FAQ
9. Final CTA

It mostly decides section order. Shared components decide how common patterns look and behave.

### `components/sections/HomeHero.tsx`

The homepage-specific hero. It contains:

- Header-transition sentinel
- Full-bleed media
- Main heading
- Supporting copy
- Check Availability action
- Explore Pricing action

The invisible sentinel tells the header when the visitor has scrolled away from the opening state.

### `components/media/CinematicHeroMedia.tsx`

Separates hero media from hero copy.

It currently displays a development poster with subtle CSS movement. It is ready for separate desktop and mobile videos with autoplay, muted playback, looping, inline playback, poster fallback, reduced-motion behavior, and stable dimensions.

The poster remains behind a future video, so video failure does not create an empty hero.

## 6. Global layout

### `components/layout/Header.tsx`

A client component because it manages:

- Current route
- Dropdown state
- Mobile-menu state
- Escape-key behavior
- Expanded and compact header states
- Intersection Observer

At the homepage top it overlays the hero. After scrolling it becomes a compact warm-white header. Other routes use the practical light header.

Navigation items are stored in arrays and mapped into links, avoiding duplicated markup.

### `components/layout/Footer.tsx`

A simpler server-rendered component containing:

- Compact logo
- Business statement
- Service area
- Verified languages
- Route links
- Prototype status

Business facts come from `lib/config.ts`.

## 10. Reusable page sections

### `components/sections/PageHero.tsx`

Shared hero for non-home routes. It supports text-led and media-based pages with availability and pricing actions.

### `components/sections/CommercialPage.tsx`

The major route-reuse mechanism.

Several pages share:

```text
Hero
→ content blocks
→ FAQ
→ final CTA
```

Routes supply different data instead of copying that structure.

### `components/sections/FAQAccordion.tsx`

Stores the open FAQ index and uses accessible buttons, `aria-expanded`, `aria-controls`, and answer IDs.

### `components/sections/PricingPlanner.tsx`

Lets visitors choose supplied pricing anchors and carry them into Check Availability through URL parameters.

It does not invent totals or discounts.

### `components/sections/CheckAvailabilityForm.tsx`

A three-step form tracking event, date, location, services, guests, budget context, and contact details.

It reads pricing-planner selections from the URL. Submission remains an explicit demo and does not claim that anything was transmitted.

## 11. Central data files

### `lib/config.ts`

The source of truth for:

- Business name
- Short statement
- Service area
- Verified languages
- Contact verification
- Social links
- Work publication status
- Pricing approval
- Submission mode
- Development labels

### `lib/media.ts`

The typed media registry.

Each media entry records:

- Canonical ID
- Public file path
- Alternative text
- Purpose
- Truth status
- Desktop ratio
- Mobile ratio
- Focal position

Components should use this registry rather than casually hardcoding image filenames.

### `lib/pricing.ts`

Imports the approved development pricing JSON, creates valid pricing-key types, formats currency with `Intl.NumberFormat`, and blocks production-stage publication while prices remain development-only.

### `lib/analytics.ts`

Defines allowed analytics events and a typed no-op `track()` adapter. Components can describe events without choosing an analytics vendor yet.

## 18. Following one request through the system

When someone opens `/weddings/`:

1. Cloudflare finds `out/weddings/index.html`.
2. That HTML was generated from `app/weddings/page.tsx`.
3. `app/layout.tsx` adds the font, metadata, header, main landmark, and footer.
4. The route selects `pages.weddings` from `lib/content/redesign.ts`.
5. It sends that data into `CommercialPage`.
6. `CommercialPage` renders `PageHero`, sections, FAQ, and final CTA.
7. Images come from `lib/media.ts`.
8. `MediaFrame` renders files from `public/images/`.
9. Tailwind classes use tokens from `app/globals.css`.
10. Browser JavaScript activates the header and FAQ.
11. Playwright verifies the route and responsive behavior.

The central pattern is:

> A route chooses data, shared components render it, centralized registries protect truth, and Next.js converts it into static files.
